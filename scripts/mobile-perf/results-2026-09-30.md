# Simulator CPU hill climbing — 30 September 2026

Four accepted changes were implemented and committed on main. A fifth candidate
was measured and discarded because it did not improve CPU or memory beyond noise.

Measurements used a dedicated iPhone 17 Pro / iOS 26.5 simulator, arm64 Release
builds, bundled Hermes bytecode, and disabled OTA in the disposable product.
Each comparison below is the median of three trials, with a five-second warmup
and fifteen-second measurement window. CPU is a percentage of one host core;
memory is Darwin physical footprint in MiB. These synthetic workloads isolate
production components, without pairing or accessing real conversation data.

| Workload | Baseline CPU | Accepted CPU | Baseline memory | Accepted memory |
|---|---:|---:|---:|---:|
| One activity diamond | 3.63% | 2.40% | 69.6 | 65.7 |
| Twenty visible diamonds | 8.76% | 6.74% | 70.5 | 66.8 |
| Twenty covered diamonds | 9.53% | <0.01% | 70.4 | 65.7 |
| Long answer, 10 updates/sec | 70.15% | 35.40% | 114.2 | 114.3 |

The long answer contains 80 completed prose paragraphs and a growing tail. Its
CPU fell about 50%; streaming memory was unchanged. Visible-marker memory fell
about 5%, and covered-marker memory fell about 7%. Idle CPU stayed below 0.01%.
These results do not establish physical-device battery or temperature gains.

## Accepted iterations

1. Replace the shared Reanimated diamond worklet with a shared native Animated
   driver and shared interpolation nodes. The original sample showed repeated
   Fabric commits under the display-link callback. Motion/keyframes and reduced
   motion remain intact; the driver does not create an interaction handle.
2. Gate repeating diamonds, spinners, skeletons, and pulsing indicators by app
   foreground state and screen/drawer visibility. Closing a drawer or covering
   the transcript releases its animation consumers; revealing it resumes them.
3. Release every thread send right returned by `task_threads` during diagnostic
   sampling. The original native routine grew one observed thread's reference
   count from 3 to 1003 over 1,000 calls; the fixed production source stays at 3.
   Simulator sampling at 100 calls/sec previously accumulated roughly 5,000
   thread references per trial; the fixed binding has no positive growth.
4. Reuse parsed completed prose while reparsing the growing final paragraph.
   Reference definitions, replacements, completion, lists, quotes, code, HTML,
   and other context-sensitive syntax retain full parsing. The existing 50ms
   streaming cadence and cross-paragraph native text selection are preserved.

An additional attempt to memoize completed paragraph views measured 36.31% CPU
versus 35.98% before it, with effectively unchanged memory. It was reverted.

## Validation and artifacts

- All 1,242 mobile tests pass; mobile typecheck and focused ESLint pass.
- The native regression compiles the production Swift sampler and checks CPU,
  memory, and zero reference growth over 1,000 calls.
- Every character prefix of all 652 [CommonMark 0.31.2 examples](https://spec.commonmark.org/0.31.2/)
  matched the full parser's AST in a temporary corpus check. This found two
  container-continuation cases; both have permanent regression tests and the
  cache now uses conservative prose boundaries.
- A stale Mermaid test also failed with the unchanged renderer. It now checks
  the existing source-during-streaming behavior and settled diagram rendering.
- Implementation commits use repo-local review:
  `.agents/skills/autoreview/scripts/autoreview --mode commit --commit <sha>`.
- Raw trials and bundle hashes are in `var/mobile-perf/*.json`; final controls
  are in `final.json`, and the final streaming result is in `safe-markdown.json`.
  The external collector's Mach timebase conversion was calibrated against a
  busy core (99.7%). Initial baseline readings were corrected from raw Mach
  units before comparison; that correction is recorded in `baseline.json`.
- Reproduce or continue the hill climb with [README.md](README.md).

The simulator has the accepted changes installed. JavaScript improvements can
ship through OTA; the sampler resource fix requires a new native build.
