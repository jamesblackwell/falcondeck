## Are our recent choices out of line?

- **200K Claude compaction:** defensible and deliberately more conservative than huge-window defaults, not a common universal threshold. FalconDeck sets `CLAUDE_CODE_AUTO_COMPACT_WINDOW=200000`, except explicit `[1m]` models. OpenClaw's 200K constant is a **fallback context window**, not a fixed compaction trigger: its managed loop uses the smaller of 75% of the active window and window-minus-reserve, with native/backend exceptions. Hermes defaults to 50%, **floored to 75% below 512K**, with further route-specific overrides. Thus 200K is not directly comparable without knowing window, reserve and retained output. Keep it and measure cold resumes. [Local implementation](../../crates/falcondeck-daemon/src/claude.rs), [O1], [O9], [H1].
- **Five parallel tasks:** within observed practice; exactly OpenClaw's ordinary child admission default, below Hermes's ten. Execution slots, admitted children and total lifetime spawns are different limits. Missing fleet/depth bounds matter more than changing five. [O7], [H8].
- **Prose-only self-edit prohibition:** weak enforcement, but not uniquely lax compared with personal-agent defaults. Hermes permits control-file writes and intentionally learns skills; its shell can bypass file-tool guards. OpenClaw's personal-assistant trust model also needs sandbox/tool policy for enforcement. For company governance, our stated prohibition needs a real boundary. [H5], [H2], [O6].
- **Always-steer messages:** **aligned with current OpenClaw's default**, contrary to older advice describing collect as the universal default. Hermes heartbeats never steer mid-turn. Keep steering for urgent blockers/corrections; proposal: ordinary bot results collect until idle, with an explicit urgent flag. Our current same-sender merge helps backlog, but has no causal loop budget. [O2], [H4], [Local behavior](../../crates/falcondeck-daemon/src/app/thread_tools.rs).
- **Five tickets/day:** a reasonable company experiment, **not a common platform default found here**. The reviewed systems bound turns, tools, delegation and spend instead. Keep it if it reduces noise; avoid interpreting it as five tasks/day or slowing legitimate execution. FalconDeck enforces a rolling 24h per bot, or collectively per provider's ordinary task threads, rather than literally every thread getting five. [Local rule](../TICKETS.md), [H7], [F3].

## What to study, and what not to copy

**OpenClaw — study first for delivery and governance.** Closest to persistent personal agents across chat surfaces, with scheduled work and native harness integration. Follow queue-mode resolution → runtime steering/fallback, and managed maintenance → compaction → memory checkpoint. Current defaults differ materially from older tutorials: steer, no automatic session reset, and ordinary automation jobs replacing heartbeat configuration. Its recommended-model list agrees with James's strong-model choices; the product does not automatically make housekeeping cheap. [O2], [O1], [O3], [O10], [O11].

**Hermes — study first for context economy.** The strongest patterns for James are bounded injected memory, narrow isolated cron work, lean summaries with exact anchors/recovery, and idle-only recurring session work. Source confirms the small-context floor that a simplistic “50% compression” reading misses; one worked example in the docs still uses the earlier 50% calculation for 200K, so use code over that example. Background memory review is useful but can replay substantial input; do not enable another autonomous maintenance loop without metering. Its intentional skill learning is a different governance choice from James's prohibition. [H1], [H2], [H4], [H8].

**OpenFang — study selectively for company budgeting.** Chosen as the one additional platform because its autonomous Hands, schedules, agent messaging and kernel quotas resemble a company control plane more closely than a stateless workflow library. The inspected main commit is from **12 May 2026**: useful source, but not evidence of November release freshness. Source review caught two reasons not to adopt it wholesale: configuration docs say keep 20 messages, code keeps 10; consolidation prose promises merging/pruning, implementation only decays confidence. The kernel's token-trigger/message-guard mismatch also weakens compaction guarantees. Borrow quota admission and accounting patterns, not the advertised defaults without tracing them. [F1], [F2], [F3], [F4], [F5], [F6].

All three are **study**, not dependencies or migration recommendations. Upstream licenses: OpenClaw MIT, Hermes MIT, OpenFang MIT; any later code reuse needs a file-level license check. [O13], [H10], [F8]. Research covered context/reset, memory, scheduling, model routing, queue/delegation, approval/self-edit and budget source paths; no platform was installed or executed. “Not established” means not verified in those paths, not a claim that no plugin can provide it.
